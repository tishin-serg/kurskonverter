# Wallet, OKX и BestChange

Оба дополнительных маршрута реализованы. Ключи читаются из environment; PowerShell `scripts/run.ps1` загружает локальный `.env` как данные. Бот не создаёт ордера и не выполняет переводы.

## Настройки

- `OKX_API_KEY`, `OKX_API_SECRET`, `OKX_API_PASSPHRASE`: чтение персональных комиссий, статуса вывода BTC и депозита GRAM. Режим комиссии аккаунта должен быть `feeType=0` (в получаемой валюте); другой режим явно отклоняется.
- `WALLET_API_KEY`: ключ **P2P integration API**, не Wallet Pay. API продолжает использовать `TON`, приложение показывает `GRAM`. Сопоставление ограничено этим активом и нативной сетью TON.
- `WALLET_GRAM_WITHDRAWAL_FEE_FALLBACK=0.05`: опубликованный Wallet тариф, проверен 2026-09-07. В P2P API нет комиссии вывода. Пустое значение отключает этот маршрут, заданное всегда маркирует расчёт как резервный. Минимум вывода — 0.1 GRAM, сетевой шаг — 0.000000001 GRAM. Перед переводом приоритет имеет тариф в Wallet.
- `BESTCHANGE_API_KEY`: официальный v2 API. Используется официальное зеркало `mirror2.bestchange.app`; ключ в пути запроса никогда не выводится в логи.
- `BESTCHANGE_FROM_CODE`: точный код безналичного рублёвого направления из API. По умолчанию `TCSBRUB` при `PAYMENT_METHOD=Tbank`, иначе `SBPRUB`. Идентификаторы определяются по справочнику, Bitcoin BEP20 и Lightning исключены.
- `PAYMENT_METHOD=Tbank`: понимает также `Т-Банк`, `tinkoff`, `TCSBRUB`. Числовые ID других провайдеров сохраняются без переосмысления. Общий Bank Transfer на Bybit не считается подтверждением Т-Банка. `/settings any` снимает фильтр только для пользователя бота.

## Что учитывается

Wallet: SELL-объявления, все страницы до 50 записей, дедупликация при смещении страниц, остаток, рублёвые лимиты, число сделок и рейтинг (доля API умножается на 100). Комиссия покупателя P2P — ноль по правилам сервиса. Вывод Wallet, продажа GRAM по bids OKX, покупка BTC по asks и вывод BTC считаются в обратном порядке точной decimal-арифметикой. Проверяются минимальный депозит GRAM, доступность сети, шаги и максимальные объёмы рыночных сделок. Прекращение доступности или ошибка обновления комиссий/инструментов исключают их из snapshot.

BestChange: расчёт по `rate`, резерву BTC и входным лимитам RUB. `rankrate` рассчитан сервисом для 300 USD и не используется как цена произвольной суммы. Предложения с непустыми дополнительными комиссиями `extra`, отличающимся `rankrate`, метками `percent`, `unstable`, `atm`, `purse` исключаются. Публичная спецификация не описывает формулу `extra`; неподтверждённые доплаты не угадываются. Поэтому сравнивается проверяемое подмножество предложений, а не обязательно весь мониторинг. Условия верификации, ручного обмена и плавающего курса передаются в подробности. Внешние комиссии банка оплачиваются по его тарифам и не известны API.

Справочник названий обменников загружается отдельно. Его обрыв не блокирует курсы: показываются ID обменника и ссылка BestChange. Частично скачанный JSON не используется. Для этого API отключено повторное использование соединения: на проверенном подключении зеркала иногда зависали при следующем запросе. Курсы обновляются каждые 20 секунд, метаданные валют — раз в час.

## Проверка

```powershell
./scripts/run.ps1 -CheckRoutes
```

Диагностика читает API и рассчитывает 0.01 BTC, не пишет в Telegram. Ненулевой код выхода означает, что при текущем фильтре доступны не все три маршрута. Для проверки всех провайдеров без ограничения банком передайте исполняемому файлу `check-routes any` при загруженном environment; это не изменяет `.env` или SQLite.

2026-09-07 22:02:56 UTC: `check-routes any` успешно рассчитал все три маршрута. Обычные тесты проверяют HTTP fixtures, подпись OKX, направление Wallet, масштаб рейтинга, дополнительные комиссии BestChange и точность decimal; live API не вызываются из unit tests.

## Выбор банка P2P пользователем

`/banks` или `/settings` открывает меню: Bybit и Wallet настраиваются отдельно. Доступные способы оплаты берутся из свежих объявлений соответствующего API; список разбит на страницы. Выбранный способ сохраняется в SQLite для пользователя и источника. Кнопка «Любой способ оплаты» снимает ограничение даже при заданном серверном `PAYMENT_METHOD`. Если метод исчез, сохранённый фильтр не расширяется автоматически. Просроченная кнопка не заменяет настройку другим методом.

В ответе с котировкой также есть кнопка «Выбрать банк P2P». `/settings any` снимает общий фильтр и очищает отдельные настройки. Прежняя команда `/settings <ID>` устанавливает общий фильтр и очищает отдельные настройки; для обычного использования предпочтительно меню.

Выбор P2P не изменяет направление BestChange: оно по-прежнему задаётся `BESTCHANGE_FROM_CODE` сервера. Изменение этого направления через меню — отдельная функция, пока не реализована.
